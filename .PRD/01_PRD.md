## 1. 제품 개요

### 한 줄 요약
Claude Code Channels(폰에서 내 PC의 Claude Code에 명령 보내기)를 **다시 설치할 때 헤매지 않도록**, 검사해서 다음 할 일을 알려주고 막힌 곳을 뚫어주는 도구.

### 해결하는 문제

지금 설치는 **14단계**이고, 실패 지점이 문서 곳곳에 흩어져 있습니다. 새 PC·초기화·중간에 멈춘 상태에서 다시 하려면 문서를 처음부터 다시 읽어야 합니다.

실제 증거:
- 이 PC의 `~/.claude/channels/discord/`에는 `.env`만 있고 `access.json`·`approved/`가 **없습니다**. 즉 **토큰만 넣고 페어링 전에 멈춘 상태로 2026-07-09부터 방치**되어 있습니다.
- 리서치 자료 4개(`RESEARCH_SOURCES-01~04`)를 공식 문서·플러그인 소스와 대조한 결과, **왕초보가 막히는 지점 8곳이 자료에 없었습니다** (§11 참조).

### 핵심 가치

| 기존 방식 | SoDam-CCC |
|---|---|
| "1번부터 읽으세요" | **"당신은 지금 7/12단계입니다. 다음은 이것"** |
| 고장나면 문서 뒤지기 | **증상 → 원인 → 조치** 를 짚어줌 |
| 문서는 6개월이면 낡음 | **현재 상태를 검사**하므로 안 낡음 |

> 이 차이가 핵심입니다. Channels는 공식 문서가 *"명령 형식과 프로토콜 규약이 바뀔 수 있다"* 고 명시한 **research preview** 기능입니다. 절차를 글로 적어두면 반드시 낡습니다. **검사형**이어야 합니다.

## 2. 사용자

### 주요 사용자
- **누구**: 나 (비개발자 바이브코더). 배포하지 않음 — PRIVATE
- **상황**: 새 PC로 옮겼을 때 / 설정이 꼬였을 때 / 중간에 멈춘 걸 다시 이어갈 때 / 6개월 뒤 다 까먹었을 때
- **목표**: 문서 안 찾고 **폰 텔레그램이 다시 통하게** 만들기

> **왕초보 말투를 유지하는 이유**: 배포는 안 하지만, 6개월 뒤의 나도 초보입니다. 형제 프로젝트 `SoDam-Loop`의 `tone` 규칙을 재사용합니다.

### ⚠️ 전제 조건 (닭-달걀 방지)

> **CCC는 Claude Code 위에서만 시작합니다.** 이걸 명시하지 않으면 *"Claude Code 설치까지 도와야 하나?"* 에서 막힙니다.

| 항목 | 상태 | 누가 |
|---|---|---|
| **Claude Code 설치·인증** | **이미 끝나 있다고 전제** | 사용자 (CCC 범위 **밖**) |
| **CCC 자신의 설치** | **PRIVATE 마켓플레이스**로 새 PC에 가져옴 | 사용자 (기존 형제와 동일 방식) |
| 그 다음부터 | **CCC가 담당** — Bun · 플러그인 · 토큰 · 페어링 · 잠금 · 마무리 | **CCC** |

```
새 PC → Claude Code 설치 → CCC 설치(마켓플레이스) → /sodam-ccc:install → 폰 연결 완료
        └─ 범위 밖 ─────┘   └─ 범위 밖 ─────────┘   └─ 여기부터 CCC ──────────┘
```

### 사용자 시나리오

**시나리오 A — 새 PC**
1. 새 PC에 Claude Code를 깔았다
2. `/sodam-ccc:install` 실행
3. 준비물을 검사하고 → 부족한 것만 안내 → 단계별로 확인하며 진행
4. 폰에서 텔레그램으로 "안녕" → 답이 온다

**시나리오 B — 중간에 멈춘 것 (이 PC의 Discord가 실제 사례)**
1. 예전에 하다 말았는데 어디까지 했는지 기억이 안 난다
2. `/sodam-ccc:status` 실행
3. **"토큰까지는 됐고, 페어링만 남았습니다"** 라고 정확히 짚어줌
4. 그 단계부터 이어서 진행

**시나리오 C — 갑자기 먹통**
1. 폰에서 보냈는데 답이 없다
2. `/sodam-ccc:fix` 실행
3. 증상을 물어보고 원인 후보를 검사 → **"권한 승인창이 PC에서 대기 중입니다. 폰에서 버튼으로 승인할 수 있습니다"**

## 4. 사용자 흐름

### 핵심 흐름
```
/sodam-ccc:status  →  현재 몇 단계인지 파악
     ↓
/sodam-ccc:install →  부족한 단계만 순서대로
     ↓
안전 잠금(allowlist) + 폰 승인 확인 + 👀 표시
     ↓
폰에서 "안녕" → 답장 도착  = 성공
     ↓
(막히면) /sodam-ccc:fix → 증상 → 원인 → 조치
```

### 검사 우선 원칙
모든 단계는 **"검사 → 필요할 때만 안내"** 입니다. 이미 된 단계는 건너뜁니다.

### ⛑️ 중단해도 안전합니다
각 단계는 **독립적**이라 **아무 때나 멈춰도 망가지지 않습니다.** 다시 `install` 하면 **끝난 단계는 건너뜁니다.**
> `undo` 를 없앤 근거이기도 합니다 — 되돌릴 필요 없이 **다시 시작하면 됩니다.**
> 이 PC의 Discord가 **정확히 그 상태**(8단계에서 멈춤)이고, 그런 상태를 살리는 게 제품의 존재 이유입니다.
자세한 검사 항목과 증상 사전은 [02_DATA_MODEL.md](./02_DATA_MODEL.md) 참조.

## 6. 보안 요구사항 (핵심 요구사항)

> **보안은 선택 사항이 아닙니다.** SoDam-CCC는 ① **봇 토큰이 들어 있는 폴더**를 들여다보고 ② **외부에서 내 PC로 명령이 들어오는 통로**를 다룹니다. 잘못 만들면 **도구 자체가 취약점**이 됩니다.
>
> 기준: **OWASP ASVS** · **Secure by Design** (나중에 덧붙이는 게 아니라 **설계 단계에서** 안전하게)

### 6.1 신뢰 경계 — 먼저 짚고 갈 것

일반 웹앱 체크리스트를 그대로 옮기면 엉뚱한 대책이 나옵니다. 이 도구의 **실제** 경계는 이렇습니다.

| 웹앱의 개념 | SoDam-CCC에서는 |
|---|---|
| 서버 · DB · 웹페이지 | **없음** — 로컬 전용 도구 |
| 로그인 · 회원 · 결제 | **없음** — 나 혼자 쓰는 PRIVATE |
| **인가 경계** | **Telegram 허용목록** ← 여기 있는 사람 = **내 PC에서 명령을 실행시킬 수 있는 사람** |
| **최고 등급 비밀** | **봇 토큰** (`~/.claude/channels/telegram/.env`) |
| **신뢰할 수 없는 입력** | 채널로 들어온 메시지 · **CCC가 읽는 모든 파일** |
| **최고 위험 권한** | **권한 승인권** — 승인하면 `Bash`·`Write`·`Edit` 가 실제로 실행됨 |

**근거 (원문·실측):**
- 공식 `channels-reference`: *"An ungated channel is a prompt injection vector."* / *"Gate on the sender's identity, not the chat or room identity."*
- 공식 `channels`: *"Anyone who can reply through the channel can approve or deny tool use in your session, so only allowlist senders you trust with that authority."*
- 플러그인 소스 `server.ts:414`: 권한 승인 요청은 **허용목록 전원에게** 발송됨.

### 🔧 왜 Remote Control 이 아니라 CCC 인가 — 2026-08-09 재검토로 추가

> **누락 정정**: 리서치 자료 **4개 전부**가 Remote Control을 언급했는데(01 §5·02 §684·03 §12·04 §548), 착수 전 PRD는 정본표·안 만드는 것·위험 어디에도 이를 다루지 않았습니다. 이 PC 실측(`claude --help`)에서도 `remote-control` 은 **표시**되고 `--channels` 는 preview라 **미표시**입니다.

**그런데도 CCC를 계속 만드는 이유는 목적이 다르기 때문입니다:**

| | Remote Control | Channels(Telegram) — CCC 대상 |
|---|---|---|
| 무엇을 원격으로 하나 | **기존 로컬 세션 화면을 앱에서 그대로 조작** | **텔레그램을 명령창처럼 사용**(자연어 메시지 전송) |
| 필요한 준비물 | Claude 앱/브라우저 로그인만 | 봇 생성·Bun·토큰·페어링·안전잠금 (**CCC가 자동화하려는 대상**) |
| 사용자의 현재 상태 | **아직 안 씀** | **이미 봇을 만들어 방치 중**(Telegram은 미잠금 상태로 가동 중, Discord는 8단계 정지) — 이 PC 실측 |

CCC의 존재 이유는 *"Channels 재설치를 자동화"* 이지 *"어떤 원격 방식이 최선인지 고르는 것"* 이 아닙니다. 사용자가 이미 Channels(텔레그램)를 선택해 봇까지 만들어 둔 상태이므로, **지금 필요한 건 그 선택을 편하게 관리하는 도구**입니다. 다음에 "왜 Channels를 쓰나"라는 질문이 다시 나오면 **이 표를 먼저 참조**하고 재조사하지 않습니다.
