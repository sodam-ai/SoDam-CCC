## Phase 1: 설치·복구 (MVP)

### 목표
> **새 PC나 꼬인 상태에서 문서를 안 찾고 폰 텔레그램이 다시 통하게 만든다.**

### 기능
- [ ] **F1 설치 마법사** (`install`) — 12단계를 검사해 **부족한 것만** 안내
- [ ] **F2 상태 점검** (`status`) — "지금 7/12단계" 형태로 진도 표시
- [ ] **F3 막힘 수리** (`fix`) — **기본은 검사 15개를 전부 돌려 실패한 것부터 제시.** 그래도 원인을 못 찾으면 **증상 사전 11건**으로 물어봄 (빈도 높은 것부터)
- [ ] **F4 안전 잠금** — `allowlist` 정책 적용을 **빠뜨릴 수 없게** (P0)
- [ ] **F5 폰 승인 켜기** — Permission Relay 확인 + 승인 방법 안내 (P0)
- [ ] **F6 마무리 설정** — `ackReaction 👀` 적용, 답변 잘림 설정 안내
- [ ] **F9 보안 자가검증** — 위험 설정 경고 + 비밀 노출 0건 자체 점검
- [ ] **📖 F10 `README.md` 왕초보 안내서** — **18개 목차**. 개발을 한 번도 안 해본 사람 기준<br>규격: [04_PROJECT_SPEC.md 문서화 요구사항](./04_PROJECT_SPEC.md) · **16·17번(문제해결·FAQ)은 [02_DATA_MODEL.md](./02_DATA_MODEL.md)의 증상 사전 11건을 쉬운 말로 옮기면 됨**

### ⚠️ 전제 조건 (범위 밖)
**Claude Code 설치·인증**과 **CCC 자신의 설치**(PRIVATE 마켓플레이스)는 **CCC 범위 밖**입니다. CCC는 그 다음부터 담당합니다. → [01_PRD.md §2 전제 조건](./01_PRD.md)

### 왜 F5(폰 승인)를 MVP에 넣는가 — 근거
공식 문서: *"권한 승인창이 뜨면 세션이 응답할 때까지 멈춘다."*
→ 밖에 있을 때 이게 터지면 **원격 사용이 통째로 무의미**해집니다.
→ 그런데 이 PC의 `telegram 0.0.6` 은 **폰 승인을 이미 지원**합니다 (`server.ts:394`, `:733`, `:84`).
→ **해결책이 이미 깔려 있는데 아무도 모르는 상태**입니다. 알려주는 것만으로 제품 가치가 큽니다.

### 완료 판정 — "진짜 제품" 체크리스트

> 웹앱이 아니므로 DB·배포 항목은 해당하지 않습니다. 대신 **실제 동작으로** 판정합니다.

- [ ] **설치 가능성(선행 조건)** — `marketplace.json`이 존재·유효하고, 새 세션에서 `/plugin marketplace add` → `/plugin install` → `/sodam-ccc:install` 슬래시 명령 인식까지 실제로 성공한다. 이게 안 되면 아래 나머지 항목은 검증할 방법이 없다(01_PRD.md S0과 동일 게이트)
- [ ] **가짜 검사 금지** — 모든 CHECK가 실제 파일/프로세스를 읽는다 (하드코딩된 "OK" 없음)
- [ ] **실전 케이스 통과** — 이 PC의 방치된 Discord(토큰만 있고 페어링 없음)를 `status`가 정확히 짚어낸다
- [ ] **실패 재현 통과** — 자동 업데이트가 꺼진 환경에서 `/plugin install` 실패를 재현하고 해결까지 안내한다
- [ ] **왕복 성공** — 폰에서 메시지 → PC 작업 → 폰으로 답장
- [ ] **폰 승인 성공** — 폰에서 승인 버튼을 눌러 실제로 작업이 이어진다
- [ ] **사람 손 최소화** — **재설치 3개 이하**(토큰 복사 · 페어링 코드 확인 · 페어링 승인) / **신규 4개 이하**(+ 봇 만들기)
- [ ] **중단 안전성** — 아무 단계에서 멈춰도 망가지지 않고, 다시 `install` 하면 끝난 단계를 건너뛴다
- [ ] **무충돌 확인** — 좀비 청소기 돌려도 안 죽음 / 안전 가드에 안 막힘 / 프로세스 안 늘어남
- [ ] **직접 조작 0건** — CCC가 파일을 직접 열어 고치거나 치환한 적이 없다. `~/.claude/` 변화는 **공식 명령을 사용자 확인 후 실행한 결과**뿐이다 (G-1·G-1b·G-1c)
- [ ] **파일 생성 0건** — Phase 1의 CCC는 **아무 파일도 만들지 않는다** (기록 파일은 Phase 3으로 이월 — A20)
- [ ] **명령 실행은 매번 확인** — 공식 명령을 실행하기 전 사용자에게 무엇을 실행할지 보여주고 동의를 받았다

## Phase 2: 상시가동

### 전제 조건
Phase 1 완료 + 실제로 재설치에 한 번 이상 써봤을 것

### 목표
> **PC가 켜져 있으면 채널이 알아서 살아 있게 한다.**

현재 문제: `bot.pid` 기록 시각이 세션 시작 시각과 같습니다 = **세션을 켤 때만 켜집니다.**
→ 정작 밖에 있을 때(이 기능이 제일 필요한 순간) 폰 메시지가 **그냥 사라집니다.**

### 기능
- [ ] 채널 세션 생존 확인 및 되살리기
- [ ] **`-p` 비대화형 모드 검토** — 공식 문서: `-p` 로 실행하면 터미널 입력이 필요한 도구가 비활성화되어 **세션이 멈추지 않음**
- [ ] **전용 최소 모드** — 폰 명령 받는 세션에 피그마·크롬·플레이라이트는 불필요 (→ 아래 주의사항 R3)

### 반드시 먼저 해결할 것 (Phase 1에서 이월된 충돌)
| 충돌 | 대응 |

## Phase를 이 순서로 둔 이유

1. **설치가 먼저인 이유** — 사용자가 직접 말한 목적이 *"내가 다시 설치할 때 편하려고"* 입니다. 그리고 설치가 안 되면 나머지가 성립하지 않습니다.
2. **상시가동을 2번에 둔 이유** — 프로세스를 늘리는 유일한 Phase라 충돌 위험(C1·C3)이 가장 큽니다. Phase 1에서 도구가 안정된 뒤에 건드려야 안전합니다.
3. **감시를 마지막에 둔 이유** — 감시할 대상(상시가동 세션)이 있어야 감시가 의미가 있고, 공식 `scheduled-tasks`로 대체될 수도 있어 **가장 늦게 결정**하는 게 낭비가 적습니다.
